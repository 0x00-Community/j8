# j8bytecode

**English** · [简体中文](README.zh-CN.md)

The virtual instruction set of [j8](https://github.com/0x00-Community/j8): an accumulator-style register bytecode
(like V8's Ignition). It only defines the bytecode; it does not parse JavaScript (that is `j8compiler`). It is the
dependency root of j8: it depends on no other j8 crate (only the `j8macros` procedural macros).

- Every type is defined in `insn.json` and generated by `j8macros::enums!` (the JSON is the single source of truth):
  instructions `Insn`, operators `BinaryOp` / `CompareOp` / `UnaryOp`, `Constant`, `FunctionKind`, `PropertyKind`,
  `Mode`, the opcodes `Opcode`, and the structs `Reg` / `Label` / `Const` / `IcSlot` / `EvalName` / `EvalScope` /
  `Draft` / `Function` / `Module`
- A function's code is bytes (`Function::code`): each instruction is a one-byte opcode then fixed-width
  little-endian operands, followed by `Insn::PAD` bytes of padding; the program counter and jump targets are byte
  offsets. j8compiler builds a `Draft` (`Vec<Insn>`), fuses it (`Draft::fuse`) and assembles it
  (`Box::<[u8]>::from(draft)`: targets become byte offsets, inline cache slots `IcSlot` are numbered). The executor
  and the JIT decode at an offset: `Function::insn_at(pc)` / `Opcode::at(code, pc)`; with `j8macros::dispatch!` an
  interpreter dispatches once per instruction on the opcode
- No text form: bytecode is stored and shipped only in the binary form, lossless: `Vec::<u8>::from(&module)` /
  `Module::try_from(bytes)`. It starts with `Module::MAGIC` (`\0j8b`; `Module::is_binary` checks it) and the
  instruction-set fingerprint `SCHEMA`, so bytecode from another `insn.json` is rejected. Function code is carried
  as is and checked once when read (every instruction decodes, every jump lands on one)

## Usage

```rust
use j8compiler::Compile;
let module = j8bytecode::Module::compile(&source, j8framework::CodeKind::Script)?; // JS ⇒ bytecode is j8compiler
let bytes = Vec::<u8>::from(&module);       // binary form
let again = j8bytecode::Module::try_from(bytes.as_slice())?;
```

The `j8dbg` tool (`debugger/`) compiles JS to the binary form (`compile`) and reads it back (`check`).
