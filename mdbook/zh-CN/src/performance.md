# 性能

## 对 V8

`samples/benchv8` 的结果（j8 带 JIT，`--runs 10`，钉在性能核上，负载低于 1）。11 个基准在三种引擎上的校验和全部一致。

| 基准 | j8 ms | V8 jitless ms | V8 ms | j8 / jitless | j8 / V8 |
|---|---:|---:|---:|---:|---:|
| fib | 1.2 | 9.0 | 1.3 | 0.1× | 0.9× |
| loop | 58.3 | 185.0 | 82.8 | 0.3× | 0.7× |
| objects | 0.9 | 13.6 | 2.5 | 0.1× | 0.4× |
| array | 40.8 | 13.0 | 6.5 | 3.1× | 6.3× |
| sort | 65.8 | 32.1 | 16.5 | 2.1× | 4.0× |
| string | 27.8 | 11.7 | 11.3 | 2.4× | 2.5× |
| closures | 2.1 | 17.2 | 2.3 | 0.1× | 0.9× |
| classes | 1.4 | 23.3 | 2.8 | 0.1× | 0.5× |
| collections | 52.8 | 27.9 | 21.3 | 1.9× | 2.5× |
| json | 24.9 | 11.6 | 11.5 | 2.2× | 2.2× |
| regexp | 12.4 | 3.0 | 1.8 | 4.2× | 7.0× |
| **几何平均** | | | | **0.6×** | **1.7×** |

（比值 < 1 表示 j8 更快。数字来自 `samples/benchv8/benchmark.md`，以仓库为准。）

## JIT 对它们做了什么

- **fib**：每个 JS 函数一个 native 函数，直接调用（参数在寄存器里、结果经第二个返回寄存器不装箱），递归调用内联两层；
  全局 `fib` 经纪元缓存读；
- **closures**：闭包内联进循环（按函数身份检查），它的上下文槽住在寄存器里，`% 100000` 变成乘法；
- **classes / objects**：构造器与方法内联，不逃逸的对象从不分配（字段当值、跨循环轮次也是：OSR 进来的循环剥一次皮），
  shape 检查与读取外提到循环外；
- **loop**：`(s + i * i) % 1000003` 里 `i * i` 超出 int32，按 double 的 int64 取余跑。

array、sort、string、collections、json、regexp 的时间花在内建函数（和 GC）里，JIT 暂时帮不上，是下一步的重点。

## 怎么量

- 计时只算编译 + 执行，每次新环境，取最短；
- 钉在性能核上（`taskset -c 0-3`）、负载低时跑；
- 看单个改动的影响要看全部基准，不只看目标那一个；
- 逐行热点可以用 callgrind；量指令数用 `perf stat -e instructions:u`。
