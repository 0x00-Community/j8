# r8 与 V8 的性能对比

同一组 JS 基准（`bench/*.js`）分别在 r8、V8 `--jitless`（纯解释器）、V8（带 JIT）上跑。V8 经 rusty_v8 `=152.2.0` 嵌入。

## 跑法

```text
cd samples/benchv8
cargo run --release                     # 三种引擎各跑一遍，出对比表
cargo run --release -- --engine r8      # 只跑一种：r8 / v8 / v8-jitless
cargo run --release -- --runs 10        # 每个基准跑几次取最短（缺省 5）
```

- V8 的 `--jitless` 是进程级开关，所以每种引擎在自己的子进程里跑。
- 计时只算编译 + 执行；每次换一个新的执行环境，取最短一次。
- 每个脚本的完成值是校验和，三种引擎要一致（表里 check 列）。
- benchv8 自成一个 workspace（根 workspace 排除了它），平时 `cargo build --workspace` 不会拉 V8 的预编译库。

## 结果

`--runs 3`，16 核机器，测时负载约 14（有别的进程在跑），数字有噪声，只看量级。11 个基准的校验和三种引擎全部一致。

| 基准 | r8 ms | V8 jitless ms | V8 ms | r8 / jitless | r8 / V8 |
|---|---:|---:|---:|---:|---:|
| fib | 160.7 | 11.4 | 3.2 | 14.1× | 49.5× |
| loop | 1243.9 | 241.2 | 107.4 | 5.2× | 11.6× |
| objects | 352.6 | 17.4 | 4.7 | 20.2× | 74.9× |
| array | 223.3 | 16.9 | 10.2 | 13.2× | 21.9× |
| sort | 257.2 | 52.1 | 21.5 | 4.9× | 12.0× |
| string | 304.6 | 16.6 | 17.4 | 18.4× | 17.5× |
| closures | 276.2 | 26.2 | 5.5 | 10.5× | 50.0× |
| classes | 511.5 | 34.8 | 4.5 | 14.7× | 114.2× |
| collections | 257.2 | 57.9 | 45.2 | 4.4× | 5.7× |
| json | 190.6 | 17.0 | 17.1 | 11.2× | 11.2× |
| regexp | 241.6 | 4.2 | 3.8 | 56.8× | 63.1× |
| **几何平均** | | | | **12.0×** | **26.5×** |

## 解读（推测，未经 profiler 证实）

- **差距最小**：sort、collections（4–5×），时间主要花在内建函数和比较回调上。
- **差距最大**：regexp（57×），可能是每轮新建正则、regress 编译没有缓存；objects / classes（15–20×）是属性访问慢：属性按字符串在表里查，没有隐藏类和内联缓存。
- 对比带 JIT 的 V8，调用密集（fib、closures、classes）差距拉到 50–114×。
